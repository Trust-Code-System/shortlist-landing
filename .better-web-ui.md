## Design Context

### Users
Customer-facing Shortlist experience. The user wants customers to find the internal pages effortless, smooth and inviting. The supplied tracker example shows customers reviewing job matches, following applications, reviewing documents and preparing for interviews.

### Brand Personality
Premium, calm, supportive. Conversational and clear. Build confidence through obvious next steps and honest status messages.

The user clarified that the portal must feel personal and client-focused, then explicitly requested restoring the earlier sidebar structure with progress cards at the top. Preserve client-specific language and specialist support within that structure.

### Aesthetic Direction
Inspired by Emil Kowalski's restraint and responsive interaction design. The user explicitly requested restoring the GitHub sales-crm colors, superseding the earlier blue preference. Use its charcoal #161616 background, #1b1d20 cards, #4124fb purple primary with #f9fbff text, #4b30ff hover and original semantic tag colors. Keep matching neutral light surfaces with the same purple accent. Default to light in both portals, regardless of OS appearance, and remember each portal’s own explicit theme preference. Use readable typography, precise spacing and restrained elevation. Replace decorative dash eyebrows with useful context labels.

### Implementation Defaults
Preserve the existing customer app: standalone HTML, shared CSS, vanilla JavaScript, Flow validation and step navigation. Use the admin portal’s Geist font, compact 254px sidebar, pill controls, flat table rows and neutral border system. Keep client-specific navigation, content and actions. The latest user requests explicitly ask to copy the admin UI, colors and sidebar movement from https://github.com/kargulstudio/sales-crm. Match its 200–400px draggable sidebar, 10px keyboard steps, saved client width and double-click reset. Below 1024px use a 254px modal navigation sheet with 350ms opening and 250ms closing motion, a blurred backdrop, Escape dismissal and focus restoration. Match popup motion and the Ctrl/Cmd+K search shortcut. Use themed scrollbars without arrow buttons and accessible custom dropdown menus. No framework migration or UI library dependency is needed. Customer-only assets must not load on index.html or in admin.

### Design Principles
The current client release is limited to sign-up/sign-in, CV and supporting document upload, admin review status, Google Meet preparation invitations, and payment. All other client tools must visibly say Coming soon and have no actionable controls: applications, employer interviews/history, CV rewriting/versions/approvals, cover letters, LinkedIn drafts, messaging, plan changes, pausing/cancellation and subscriptions. Blurred, inert previews are appropriate for future sections. The admin UI and landing page are outside this scope. Existing account, upload and payment interactions are explicitly local UI previews, with no real authentication, admin submission, invite delivery or verified charge.

1. Make the next customer task obvious before adding decoration.
2. Group related information with spacing, weight and restrained surface changes.
3. Make presses and state changes respond immediately; keep transitions below 300ms.
4. Adapt navigation and dense content for touch screens; preserve every customer action.
5. Support keyboard navigation, visible focus, reduced motion and explicit preview limitations.

The user subsequently extended the same release scope to the admin portal. Keep its existing visual system and sidebar movement, using the requested original GitHub purple primary color with readable secondary labels in both themes. Active admin sections are client records, document review, preparation invitations, and payments; all other admin routes show Coming soon. Admin review and invite actions are local previews using sample records, with no real document viewing, submission, invite delivery, or payment verification.

The latest request also authorizes specific landing-page refinements: replace decorative eyebrow dashes with small purple dots, reduce the gap below the fixed header, and replace yellow accents with the site’s purple/lavender palette. Keep the landing-page structure and copy otherwise unchanged. Use pale lavender highlights behind dark text and the original purple with light text on selected controls.

The user also requests a polished admin sign-in page and purple scrollbars without arrow buttons across the website. Keep the existing sign-in validation and allowlist session gate. The login design should feel calm, personal, and focused on the team’s client-support workflow, with a clear email field and restrained decorative document imagery.
